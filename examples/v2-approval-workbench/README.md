# v2 授权工作台的验证证据

本目录对应 [v2 授权审阅实现](../../docs/implementation/m3-v2-approval-workbench.md)，推进 [统一路由 #23](https://github.com/zhouy1017/Karajan/issues/23) 的用户确认入口。全部运行材料均为明确的本地合成数据；页面确认不启用执行配置、调用模型或创建实际 Attempt。

`author-freeze.json` 绑定作者的产品、测试与实际结果。原始失败和后续通过分别保留，不能把直接通过的新增测试描述成修复前失败。

`root-browser-initial.json` 记录最初冻结源码的真实浏览器观察，并从只读 SQLite 核对持久结果：在已勾选的第一版计划背后提交第二版，旧确认被拒绝，页面读回收窄后的范围并清除勾选；重新审阅后确认第二版，刷新仍保留批准。另验证原有 v1 页面确认，每个 Run 仅保存一条批准，`dispatch_enabled=false`。该报告明确绑定初始源码，后续修复的验证另存，不覆盖原观察。

`root-browser-quantity.json` 绑定修复后的源码与构建文件。在独立合成状态中，真实页面完整显示后端已持久化的 `USD 0e0`，勾选后成功批准原计划；只读数据库核对原值、计划与路由摘要、唯一批准以及未启用派发。

[独立 Spec](spec/README.md) 和 [Standards](standards/README.md) 分别保存自己的输入、结果和源码绑定。Spec 的 12 项认证 HTTP 路由检查与 14 项组件交互检查通过；Standards 的 11 项检查通过，原金额表示 P2 已关闭且无遗留发现。HTTP 材料使用公开项目/规划命令及认证路由生成；组件交互使用 jsdom 和 fetch 替身，真实浏览器证据另列。原失败由修复后的同一输入确认结果，不重复计入不同审查线。

作者最终全量前端回归为 153 passed，Web 回归为 65 passed；类型、格式、构建与 Ruff 检查通过。精确命令及修复前后的数量由作者冻结记录分别保留。CI 结果在提交和 PR 发布后按实际运行记录。

`root-base-integration.json` 与同名 JUnit 记录对齐已合并的 #47/#48 基线后，179 项 Web、容量与 Go 离线边界检查通过，96 个后端源文件 mypy、Ruff 及前端类型/格式检查通过。冲突只涉及 README 说明；作者的七份源码/测试/实现说明摘要保持原样。`root-freeze.json` 是整合前的暂存快照，原记录不随 README 或基线变化改写。

此处验证完整范围展示、确认身份和读取/发送边界。真实来源资格、可信路由输入组装、原子资源准入及多 Agent 派发仍由后续任务验收。
