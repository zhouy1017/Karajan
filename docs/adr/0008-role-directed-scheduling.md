# 由获授权角色决定任务拆分与调度，不内置 Agent 人数上限

日期：2026-09-14，产品设计 r8。状态 accepted 表示用户已要求该方向，**不表示代码已实现、真实并行已通过或任何 Workflow 已部署**。

用户要求任务分工由 Workflow 中配置的调度器、Commander 或其他受权角色根据实际需求决定，不能固定为前端/后端，也不能以 Karajan 内置的 2、4 等人数限制任务规模。r7 虽允许自定义角色/步骤，但预先冻结完整图和默认两个 writer 的表述仍会将运行压回静态计划。

## 决定

Workflow 可以包含获用户明确授权的计划/调度角色。该角色在既定工作契约内动态发现、拆分和扩展子图，绑定角色/来源、调整优先级与依赖并决定派发。通过当前 grant 校验的命令自动生效，不逐子任务重新请求人工批准；超出授权的目标、工具、来源、预算或交付权限才需要新的决定。

可信引擎保留唯一身份校验、资源准入、状态提交和副作用执行边界。它执行角色已经作出的业务决定，不另建隐藏的固定拆分策略；角色不能直接持有数据库、OS 或交付凭据。可委派权限绑定实际执行身份、父链与可验证范围，多角色竞争使用幂等命令、图 revision 和 CAS 处理。

冻结的是部署定义、初始输入和用户授予的可变范围；任务图在该范围内生成不可变、可追溯的修订。已启动 Attempt 的输入、Profile、来源与权限保持固定。扩展集合须闭合后汇合，已承诺的验收义务和被引用产物不能用删节点、改 optional 或新图身份抹去，消费与修复累计不清零。

产品不内置 Agent 总数或默认并发人数。用户可以显式配置并发/预算政策；真实同时运行规模还受上游、宿主和执行器资源约束。资源不足排队与背压，不能截断合法任务集。每个工作区一 writer 是写入互斥，不是全项目或全产品的 Agent 上限，也不表示系统具有无限吞吐。

## 承接与后果

本决定扩展 [ADR 0006](0006-configurable-roles-and-workflows.md) 的自定义流程，修订旧“默认两个 writer”和“所有新增子任务都要人工批准”的活动语义。[ADR 0001](0001-single-coordinator.md) 的唯一可信协调器仍成立，但不限定只有一个角色能作获授权的业务调度判断；用户选定主 Commander 的任期交接要求保留。

[ADR 0005](0005-external-model-gateway.md) 的外置网关与受控 runtime 边界、[ADR 0007](0007-conversational-workflow-deployment.md) 的真实配置/同源预览/部署读回，以及 [ADR 0003](0003-independent-delivery.md) 的 PR 证据和独立交付门继续有效。原 Issue、固定规模示例与失败证据保留其范围，不升级为 r8 通过。

实现需补充有界调度 grant、角色决定回执、动态图事务和开放/封闭汇合语义，而不只把 max_agents 配置改成更大的数字。角色判断按可信事件触发，机械资源重试和 UI 刷新不轮询模型。契约与 RS-AC01–10 见 [角色主导调度](../architecture/11-role-directed-scheduling.md)，包括同一流程的 1/3/7 需求规模、原范围自动执行、背压、越权、竞争恢复、写区互斥、Attempt 冻结和不可删减的完成义务。
