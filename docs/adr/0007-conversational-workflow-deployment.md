# 对话 Agent 生成 Workflow 配置，图表确认后实际部署

2026-09-14 用户明确 Workflow 设计应由对话式 Agent 接收文字要求，撰写对应配置文件，借助流程图和表格让用户确认/修改，并真实部署。本决定承接 [ADR 0006](0006-configurable-roles-and-workflows.md)，将“表单/API 先行”的产品入口改为 Designer 对话主导；API 是工具接口，图表与配置编辑辅助对话。

Designer 是 Commander Hub 内的设计能力，可配置职责和模型来源，负责生成和修改候选配置。服务端从同一配置解析、校验并生成流程图/表格；用户文字或表格修改都形成新文件版本。用户批准绑定所见配置包、编译预览、部署目标和适用执行范围，不能只确认一段与真实配置不一致的模型摘要。

可信部署器物化获批配置为 pending 包，调度器准备加载并读回就绪后，条件切换 active 版本并形成部署回执。配置保存、模板发布、实际部署、Run 启动与结果验收分别记录；一次“确认并部署”可完成前几项，一次明确“部署并运行”可覆盖具体 Run 的批准，无须重复询问同一授权。Designer 不持有部署主控权，不直接写活动配置或自行批准。

部署切换只作用未来绑定该版本的 Run；既有 Run 固定原批准。加载失败、回执丢失或部署竞态按原身份核对，不以模型自述或文件存在宣称部署完成。详情与验收见 [对话设计与部署契约](../architecture/10-conversational-workflow-deployment.md)。本次为产品设计修改，尚未实现 Designer 或部署真实 Workflow。

r8 [ADR 0008](0008-role-directed-scheduling.md) 承接运行阶段的受权调度：部署配置可以声明动态扩展点及 SchedulerGrant，初始确认无需枚举未来所有子任务；授权内图修订不重新部署模板或逐项人批。定义发布与已有 Attempt 仍保持原冻结语义，配置图和实际运行图分别展示，不把未来动态节点伪装成已确定内容。
