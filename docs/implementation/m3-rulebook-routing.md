# M3：Rulebook 编译与确定性路由

本切片关联 [M3-01 #23](https://github.com/zhouy1017/Karajan/issues/23)。固定任务、批准范围、资源目录及容量快照现在可以交给同一个纯求解器，得到规则命中、全部候选、淘汰原因、多池压力、排序值和最终选择。严格编译器检查矩阵及组引用，拒绝结构错误，标出静态歧义，并区分执行内容摘要与版本身份。

## 已实现行为

硬约束先于排序：任务就绪状态、可信风险下限、角色能力证据、Profile revision、工具与上下文、隔离和数据去向都必须满足。候选取项目、原 Run 授权上限、当前批准范围及冻结组成员的交集。质量升级只激活当前获批阶段的单个组，检查失败原因及剩余修复轮次；扩大新规则组不能自动扩大旧批准。T3 Review 要求独立上下文与不同作者模型家族。

容量逐个检查适用池和完整需求向量，保留服务报告、本地待核对、未来预留、安全余量及角色保护的独立分量。主 Commander 的保护量和并发名额对 Worker、顾问和显式禁止使用保护的 lead 均不可用。未知需求或观察必须符合有限保守模式；更小的保守并发上限也扣 Commander 保留名额。已量化池压力取最大值；没有可计算值时为 null，混合未知池仍保留未知档位。

现金路径要求逐调用上界、完整调用覆盖和有效价格，分别检查授权、配置预算、剩余预算和账户余额的原币限制。FX 只用于排序；候选集合缺任一所需参考汇率时，全体跳过现金排序项。未知值不会被当成零。

所有入口的结果保持 `activation_allowed=false`。求解器不读取数据库、系统时间、账户或密钥，不创建预留或启动进程。完整输入与算法身份随输出保存；CLI 另记录所有后端 Python 源文件摘要。原生配置中出现凭据字段时，整体拒绝且不回显输入。检查助手从项目配置模块提取为公共函数，保留既有导入接口和行为。

## 使用与证据

公共函数、四份 JSON Schema、固定输入及 CLI 命令见 [回放说明](../../examples/routing/README.md)。`fixture_from_configuration` 只生成明确的本机合成事实，不用于把普通账户配置变成合格执行快照。`published-report.json` 为提交源码的实际 CLI 输出；早期 `fixed-report.json` 与 `fixed-report.final.json` 保留为历史。

2026-09-06，最终 Windows 路由专项 **78 passed / 1.50 秒**，独立 Standards 重跑 **78 passed / 5.11 秒**；最终 WSL2 路由专项 **78 passed / 4.87 秒**。WSL 的一项提示为共享目录 pytest 缓存写权限，不影响测试结果或 JUnit 输出。公共凭据助手变更后的既有项目、Run、Web 回归 **150 passed / 27.89 秒**。最终全仓 Ruff 和 87 个后端源文件 strict mypy 通过。

在最后一项预算输入验证修复前，Windows 全仓后端测试 **726 passed、12 skipped、52 subtests passed / 295.41 秒**，记录为 `windows-full.junit.xml`。跳过项为 POSIX 权限、Linux namespace、WSL PE 控制及 POSIX 符号链接条件；两项警告来自测试客户端依赖弃用。该全仓记录不包含后补的 5 个预算测试；最终源码的完整远端结果另随实际 PR 提交记录，不把定点重跑冒充全仓重跑。

独立 Spec 的五份原输入及最终复验证据由 `review-fixes/spec-final-index.json` 绑定：未知需求、lead 禁用保护、数值等价 FX、原生假秘密以及混合池压力均已闭合。Standards 的非法目录预算反例现返回结构化 `POLICY_SNAPSHOT_INVALID`，见 `budget-number.*.json`。编译器额外记录了权限布尔值、静态歧义及非 ASCII 摘要回归；保守并发扣保护名额的独立反例另存。两轴最终审查均无未闭合发现。历史失败保持原文件；未保存旧源的记录不宣称可在旧提交重新执行。

提交整理只删除公共凭据助手文件末尾的一行多余空行，函数内容逐字节未变；变更前后摘要记录在 `source-format-change.json`。整理后再次通过 78 项路由测试（1.46 秒），五个原 Spec 输入的公开结果与先前最终报告完全相同，见 `publication-replay.json`。`freeze.report.json` 记录测试时工作目录源码与所有历史证据。

首轮逐字节提交校验发现，两份既有适配器文件在 Windows 工作目录使用 CRLF，Git 中使用 LF，因此原始字节摘要不同；已确认仅换行表示不同，产品内容未变化。`commit-source-binding.json` 保留此次校验差异，将 87 份源码映射到实现提交 `90e8575` 的实际 Git blob 摘要；全部测试与证据文件逐字节一致。跨检出重放比较输入和结果时，应另外核对源码表示，不能把换行差异当成相同原始摘要。

## 接入边界

这些输入是模拟事实。求解器检查一致性，不能证明调用者提交的授权摘要、当前策略标记、作者或观察出处是真实权威。Host 后续必须从批准记录、固定 Profile、当前容量账及可信风险规则构建快照，并在启动事务内重新检查、预留和写入 Attempt/outbox。

当前项目配置、Run、Host 和 Web 尚未切换到该求解器；规则编辑、版本发布、旧 Run 的显式采用和真实统一准入仍待实现，安排见 [接入与发布计划](m3-rulebook-publication-plan.md)。本 PR 不关闭 M3-01，不将 FR06、AC03 或 A11 的完整产品验收标为通过。真实模型及现金 API 请求数为零，真实来源资格仍为 `not_run`。
