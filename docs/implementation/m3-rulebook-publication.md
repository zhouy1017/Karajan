# M3：Rulebook 版本发布与旧 Run 固定

本切片继续 [M3-01 #23](https://github.com/zhouy1017/Karajan/issues/23)。项目现在可保存不可变规则版本，经服务器预览后发布；旧 Run 继续使用批准时固定的规则，同时服从当前资源撤销。发布只改变后续配置，没有取得真实模型执行资格。

## 发布与资源权威

沿用 `ProjectRegistry` 的项目 SQLite 数据库。不可变执行版本、追加发布记录、当前项目配置指针和幂等回执在同一事务内写入；相同 id/revision 不允许换成另一份执行内容，修改说明文字不改变执行摘要。旧完整配置入口遵守同样约束，可保存结构可存储的无效草稿，但不能借此发布结构无效规则或覆盖已经固定的版本。

服务器预览绑定 owner、项目版本、完整配置摘要、编译器身份、有效资源目录及过期时间。确认只接受该预览。相同命令重试返回已保存的原回执；过期、内容变化、旧编译器、其他主体和并发冲突均拒绝。空能力组或资格缺失可保存合法的规则版本，并显示 `waiting_qualification`；所有发布回执均保持 `activation_allowed=false`。

当前有效资源目录与草稿分开记录。已明确保存的合法停用、撤销批准和资格变化即时成为当前限制；非法预算或引用的草稿不能恢复已撤销权限。旧库迁移按已应用配置历史恢复最近有效目录，不从任意未应用预览取得权限；历史同版本冲突明确列出，旧预览必须重新生成。

## 旧 Run 与实际本机启动

串行协调器从 Run 保存的配置计算规则、预算、组成员和协作限制。发布新规则、扩大组或未来预算，不替换旧 Run 的输入摘要。当前资源目录只收窄可用范围：Profile 停用、批准撤销、执行身份、隔离、数据通道或必需能力证据变化会阻止旧任务继续。

本机启动边界依次保持协调事务、Run 当前批准和项目当前资源视图，重新核对后才创建并启动 Host Attempt。撤销或计划更新先提交时，旧任务不会启动；Host 先接受时，更新等待该步骤结束，下次推进处理失效。崩溃不会抹去 Host 已接受或结果未知的启动身份，恢复继续核对原 Attempt。

这部分仍是既有固定模板的串行本机执行。自定义矩阵在旧预览入口明确返回 `ROUTING_SNAPSHOT_REQUIRED`，完整纯求解器另有入口。此启动锁没有替代共享 CapacityPolicy、全部配额池、现金账和 Host outbox 的统一原子准入。

## 工作台

项目的“调度规则”页面提供矩阵优先级、候选组、质量升级组、能力组成员、排序与三个协作数量上限的编辑。复杂条件可通过完整规则文件导入导出；已确认的全局和固定协作约束保持锁定。发布前展示相对当前保存内容的差异、编译诊断、缺失资格及版本历史，确认调用已认证的服务器发布接口。

编辑使旧预览失效。版本冲突读取最新权威并保留用户编辑，要求重新预览。发布发送前在当前标签页保存原命令和编辑；同登录会话内跨项目、页面或刷新都恢复该请求，未知结果只允许显式重试原命令。存储不可用时不发送。退出后新会话通过发布历史核对结果，不恢复旧会话的重试身份；关闭标签页也不承诺保留本地未决编辑。页面不启动模型；模拟页面、显式采用新规则及统一调度尚未接入。

## 验证与范围

测试与审查原输入见 [发布证据](../../examples/rulebook-publication/README.md)。Windows 联合项目、路由、串行协调、Run 和 Web 测试 **322 passed、1 POSIX 条件跳过 / 115.29 秒**；WSL2 项目、14 项新启动用例和发布 HTTP 测试 **131 passed / 21.08 秒**。WSL2 首次收集因既有环境缺少 FastAPI 失败，补齐项目固定 Web 依赖后重新运行通过；没有把收集失败当成产品缺陷。全仓 Ruff 与 89 个后端源文件 strict mypy 通过。

发布后端独立 Spec 复验的两份原输入均通过：旧库最新无效草稿不丢此前撤销，`NaN` 预算草稿不恢复权限。HTTP 独立审查覆盖未登录、重复请求头、额外字段和跨项目预览。旧 Run/启动锁的两轴独立审查各通过 14 个公开用例。前端最终 **90 项交互测试 / 11.03 秒**通过，类型、格式和构建检查通过。未决发布跨导航丢失的唯一 UI 审查问题已用原输入独立复验通过；审查者另行执行 42 项 UI、10 项原 HTTP 测试及 9 项额外 HTTP 检查，均通过。各范围的最终审查无未闭合确认问题。

实际浏览器在本机离线项目调整规则版本、说明、任务优先级、能力组成员与 Writer 上限，生成服务器预览后确认发布，再刷新当前版本并展开历史。项目 revision 从 2 到 3，规则从 v1 到 v2，历史展示两个不可变版本和一条 `waiting_qualification` 发布记录。预览前后当前配置指针及账本不变；发布前后所有 Run、容量表的逻辑摘要与 Profile 启用值不变。详见 `browser-verification.json` 和三份原始持久快照；未将组件 mock 的未知响应测试冒充浏览器断线验证。

当前仅完成 FR04/06、A11 的发布、旧 Run 固定和撤销边界子集。显式规则采用、完整模拟工作台、统一 F03/F05 接线及真实来源资格仍未验收，因此不关闭 M3-01。真实模型与现金 API 请求数为零。
