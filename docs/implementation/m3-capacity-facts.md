# M3：从容量账本读取可信路由事实

本切片推进 [共享配额 #24](https://github.com/zhouy1017/Karajan/issues/24) 与 [统一规则 #23](https://github.com/zhouy1017/Karajan/issues/23) 的接线前置。`CapacityStore.routing_facts()` 从已有 SQLite 账本读取账户、窗口、观察和占用；后续组装器可以引用这些事实及其摘要，不必从资源页面显示的余额反推。

## 接口与一致性

调用可选择完整账户，不能只选择其中充足的窗口。未指定账户时返回全部；重复或未知账户明确拒绝。接口以 `mode=ro` 打开已有数据库，设置只读查询，在一个读取事务中固定数据版本，再从 Store 的可信时钟捕获一次时间。读取不创建数据库、不迁移、不使预留过期，也不写命令或生命周期事件。

返回不可变 `CapacityFacts`，包含 `canonical_json`、`sha256` 和返回独立副本的 `as_dict()`。内容记录 schema/算法版本、捕获时刻、所选账户和按账户范围计算的来源摘要；它不伪造全局递增 revision，也不声称多库读取具有原子性。后续实际准入仍须重查当前事实并原子预留。

## 保留的容量语义

每个账户保留当前 Policy revision、所有适用池、所有 Run 共享的占用、原始 Admission/生命周期/usage/failure，以及冷却和耗尽状态。active/unknown 超过期限仍占用；到期且未发送的 reserved 只在本次投影中排除，原存储记录保持不变。并发计数沿用现有保守占位语义，不冒称已精确区分本地与服务端并发。

每个池保留最新已应用观察及其 sequence、来源、接收时间、覆盖引用和覆盖 ID，另保留耗尽判断需要的历史数值观察。报告剩余、未覆盖消费和未来预留分别输出：例如 `80 / 3 / 5` 不会先折算为 72 再供路由器重复扣减。固定窗口只有明确的归属和 reset 证据才能排除旧消费；滚动或未知归属不因时间过去就清除。

缺少观察、unknown、过期、耗尽、超限报告均明确保留。`used > limit` 产生的负剩余和超过单值范围的聚合量不会被归零，结果标明当前路由数量契约无法直接承载。来源为 official 也不会自行补出已校准置信度或有效期。

## 验收范围

Windows 全容量 **77 passed / 4.39 秒**，包含新增 26 项；独立 WSL2 全容量 **77 passed / 6.00 秒**。真实 SQLite 用例验证所有表在导出前后不变、固定时钟的重复结果、特殊路径和数据库缺失、覆盖/窗口/多 Run 占用，以及另一连接实际提交 Policy/usage 时的完整旧/新快照。全仓 Ruff 和 91 个后端源文件 strict mypy 通过。独立 Spec 的 10 项用例与 Root Standards 均无遗留发现，实际记录见 [证据目录](../../examples/capacity-facts/README.md)。远端检查在提交后记录。

该接口返回 `capacity_fragment`、`activation_allowed=false`，列明仍缺的任务授权、执行资格、需求估计和现金/价格事实。它没有补造现金余额、需求、Profile 资格或权限，也不是 Admission/Host 凭证。当前尚未完成真实调度准入接线；真实来源资格仍为 `not_run`，本轮现金 API 调用为零。
