# Rulebook 求解器接入与发布安排

本文件把已确认的 [M3-01 #23](https://github.com/zhouy1017/Karajan/issues/23) 和[路由规范](../architecture/02-routing-and-quota.md)落实到现有模块接缝。它描述后续工程工作，不是已验收能力，也不重新打开既定产品决定。

## 已发现的接缝

以下记录编译器切片之后的接入起点。当前发布、工作台与旧 Run 固定的实际进度和证据见[发布实现说明](m3-rulebook-publication.md)；余下采用、完整模拟与统一准入仍按此顺序推进。

`ProjectRegistry` 已有持久配置预览、主体/命令绑定、过期版本拒绝和原结果重放。其当前 `can_apply` 允许保存有问题的草稿，不能被用作“规则可以发布”的条件。配置验证仍要求固定模板；`evaluate_task` 仅供固定规则离线预览，不具备完整资源排序。

`RunPlanner.create` 已保存完整配置快照及授权上限。但串行协调的 `orchestration.binding.material` 仍读取项目当前规则，再以配置摘要不一致拒绝旧 Run。发布新规则与旧 Run 是否继续需要一起处理，不能仅新增发布接口就宣称已满足 A11。

当前共享容量账已有只读资源视图，但它不是完整路由输入：还缺可信任务需求估计、Profile 工具/上下文事实、原币现金上界与价格引用等。不得用页面数字自动补出这些事实，或借模拟调用会写预留的 `admit`。

## 接入顺序

1. **冻结严格编译器与同一个纯求解器。** 编译输出规范内容、可执行字段摘要、算法身份和诊断；显示说明与执行摘要分开。固定任务、规则/授权、当前资源快照驱动模拟，完整解释候选、淘汰和排序。此步骤不访问数据库或网络，不启用 Profile。
2. **沿用项目配置的唯一发布权威。** 在项目数据库保存不可变 Rulebook revision、发布记录和当前配置引用。所有能应用完整配置的入口也遵守相同版本身份约束，避免旧配置入口绕过发布校验。可保存无效草稿，不能发布结构无效规则；空组或真实资格缺失形成明确的不可派发诊断。
3. **服务器保存预览，用户确认确切版本。** 预览绑定主体、项目/规则版本、内容摘要、编译器身份与资源目录版本，展示差异。发布只应用该预览；过期对象或编译器变化要求重新预览，同命令重试返回原结果。导入内容只能生成新预览，不能导入可应用的预览身份。
4. **让旧 Run 保持已固定规则。** 正常发布不替换 Run 或 Attempt 的规则。执行时继续使用 Run 固定或明确采用的版本，另外检查当前 Profile 撤销/停用和共享 CapacityPolicy；不能为了固定规则而忽略这些当前限制。
5. **增加显式规则重评估。** 先给出影响预览，再由 owner 应用。Run 域追加采用记录，绑定当时的 Plan/Task/授权和新 Rulebook/编译器，不覆写原配置快照或历史批准摘要。候选始终与原 Run 授权上限及当前批准计划取交集；不扩张来源、Profile revision、计费通道、路径或预算。改变协作或验收语义时沿用现有计划修订与批准流程。未接通在途停止/核对前，尚可能激活、仍拥有写权或停止尚未确认的 Attempt 阻塞采用，不靠少数状态名穷举；已经停止但账单未知的消费另行保留核对，不与物理写权混为一谈。
6. **接工作台并验证真实动作。** 矩阵编辑、能力组、模拟解释、版本差异、发布确认与冲突重载都走上述服务器接口。模拟和实际派发最终使用同一求解器；切换既有调用方时补原行为回归，不能长期维持两套派发判断。

## 验收要求

除纯求解器的风险、资格、所有池、unknown 和跨币种排序测试外，发布切片必须通过：同版本不同执行内容拒绝、说明文字变化不改变执行摘要、旧预览/编译器拒绝、同命令未知结果只发布一次、扩大组不进入旧 Run、当前资格撤销仍有效、规则采用不迁移在途 Attempt、真实页面完整编辑至发布，以及实际容量/现金账和 Host 启动记录在模拟前后不变。

实现与证据分批关联 #23，只有完整接口、页面与旧 Run 行为通过后才关闭该任务。真实 F03/F05 接线和来源资格另有 gate；可控模拟事实不得被转换成真实资格通过。
