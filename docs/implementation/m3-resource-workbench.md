# M3：共享资源与 Commander 保护设置工作台

本切片关联 [M3-02 #24](https://github.com/zhouy1017/Karajan/issues/24) 和 [M1-06 #16](https://github.com/zhouy1017/Karajan/issues/16)。已登记的账户和额度池现在可以从工作台读取；用户可以修改当前账户的 Commander 保护量及保留并发名额。页面读取实际共享 SQLite，改值对随后内部准入使用的当前策略生效。

## 可操作范围

登录本地工作台后选择“资源与配额”，按账户查看服务额度、平台分配额度、窗口、报告剩余、报告上限、本地待核对用量、未来预留、安全余量和 Commander 保护量。Worker 与主 Commander 的估算可用量分别计算；在途与等待核对任务按账户汇总。服务失败引起的冷却及已知额度耗尽另行显示。

来源和报告时间、接收时间、重置时间、明确覆盖的用量数量均可查看。本机样例明确标记为“本机样例”。缺少报告、未知数值、报告过期或来源不符合当前策略时，估算显示“暂不可估算”，不把未知写成零。上次报告值仍供核对；“最近读取”表示快照读取时间，不表示服务刚刚报告。刷新按钮重新读取；此页暂不使用实时推送。

“调整保护量”只修改现有账户的 `lead_reserve` 和 `lead_reserved_slots`。并发保留不得超过账户并发上限；额度保护不得超过当前已报告池上限。额度上限与剩余量不同：允许保护量大于当前剩余，这会使 Worker 等待。未知上限不会被伪造为已知数值。未配置策略的账户不能从该表单创建策略。

## HTTP 与持久边界

- `GET /v1/resources` 在一个事务中读取池、当前策略、观察、未结束预留、用量和失败事实；它不发模型请求、不创建预留，也不将失联执行当作结束。
- `POST /v1/resources/policy?account_id=...` 要求当前所有者会话、Origin/CSRF、`If-Match` 和幂等键。账户身份放在查询参数中，避免 `.` / `..` 被浏览器当作路径处理；重复账户参数和正文身份不匹配拒绝。
- 字段限制、当前策略比较、上限检查和新 revision 写入在同一事务完成。拒绝不留下半更新；同键同正文重试返回原始回执，即使之后内部策略已变化。旧 revision 的新命令返回 409。
- 更新不会删除预留、消费或观察历史。前端遇到版本冲突先载入当前值供用户重新调整；未知网络结果保留同一份输入的幂等键。卸载、退出或 CSRF 代际变化后，旧读写响应不得修改新页面或清除新会话。

当前 API 没有账户登记、观察导入、人工校准或准入执行入口。底层 CapacityStore 仍是受信任的内部接口；页面上的估算数字不是执行授权，也不是其他客户端不会消费的保证。

## 验证与限制

后端公共测试覆盖真实 SQLite 的只读快照、当前策略更新、重复提交、版本冲突、重开持久化、身份和认证拒绝、未覆盖消费/未来预留区分、未知/过期/耗尽以及报告上限。前端交互测试覆盖编辑、冲突重载、未知结果重试、会话代际和数值验证。独立审查的原输入及修复前后记录保存在 `examples/resource-workbench/review-fixes/`；旧实现未单独提交的历史观察不宣称可从当前源码重现。

2026-09-06，Windows 后端容量与 Web 套件 **79 passed / 6.12 秒**（`examples/resource-workbench/windows.junit.xml`）；前端全部 **48 passed / 7.48 秒**，包括资源页的 30 项专项交互测试；全仓库 Ruff、78 个后端源文件 strict mypy、前端类型/格式检查与生产构建均通过。两项提示来自测试客户端依赖的弃用警告，不涉及执行失败。

实际浏览器使用本机服务与“离线样例账户”：打开三个共享窗口，确认每周报告剩余 5、本地待核对 1、未来预留 2、Commander 保护 2，Worker 估算为 0；将保护改为 1 并保存，随后整页刷新重新打开，保护仍为 1、Worker 估算为 1，主 Commander 估算仍为 2。当前策略从 revision 1 变为 2；2 条预留、1 条用量和全部观察的联合摘要前后均为 `2e02b36bebcf1fc0bc5c5a4c5b6e4f508e904c3c586a7f2172b908923d0ee0d0`。见 `browser-before.json` / `browser-after.json`。

随后仅通过内部接口注入一份明确的本机未知报告，再点击页面刷新；每周窗口显示“额度未知”，两种角色均显示“暂不可估算”，仍显示 1 次待核对和 2 次未来预留。输入与快照见 `browser-unknown.input.json` / `browser-unknown.json`。该步骤证明页面反映当前真实存储的可控观察，不证明服务商能提供该报告。浏览器窄窗口中导航、编辑按钮和额度卡片均可见，未发生横向裁切。

独立 Standards 与 Spec 复核均无未闭合发现。原始点段账户、超过池上限、无首份报告时的耗尽、旧会话迟到 401 四类反例已复验；[Spec 重跑入口和命令](../../examples/resource-workbench/review-fixes/spec-README.md) 保留原输入与历史失败。`freeze.report.json` 绑定最终源码、验证结果与浏览器记录；GitHub 必需检查须另以实际提交结果为准。

真实来源观察、统一调度与启动 outbox、排队公平性、完整 Run 事件视图和账户登记仍未由此页验收；M3-02 和完整 FR08/FR09 保持实现中。没有真实模型请求、现金 API 调用或资格启用，`live_qualification=not_run`、`activation_allowed=false` 保持。
