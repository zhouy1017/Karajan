## 1. 审计状态和证据规则

每项分别保存实现状态 `未实现 / 实现中 / 已实现待验收 / 已验收`，以及验收结果 `not_run / passed / failed / unsupported`。D01–D09 的设计决定已经 accepted；表中的未实现只描述落地，不能理解为重新打开用户选择。

- **文档、fixture、schema 和 Issue 关闭不是行为证据。** 可运行实现通过有明确输入/输出的测试后，才可填写该测试覆盖部分。一个 fixture 文件存在或断言内部函数被调用不足以通过。
- **允许在正确层级使用假依赖。** 对规则、原子账本、外部观察和错误分类，可用可控 provider/报告注入，经产品入口验证实际状态和发送记录；这证明程序行为，不证明某真实来源的认证、配额、计费或隔离能力。
- **真实资格单列。** 同一个协议、runner 或模型名称不让另一个账户/通道继承 passed。资格绑定 Profile/runtime revision、OS/隔离、工具路径、认证和计费形态；变更后按影响重验。
- **产品 gate 与外部事实单列。** 本地检查、独立 Review、push、PR 创建、当前 commit 的 CI 和用户 merge 分别记录。旧 SHA 的通过不能授权新候选；模型自述、进程退出 0、PR 页面存在均不能代替其他门。
- **父要求取所有必需子用例的合取。** 一个 happy path 不关闭 FR；Axx 有 M0 原语证据仍不表示完整 Axx 通过。failed/unsupported 研究票可以完成调查，但必需能力未通过则对应产品出口仍阻塞。
- `not_applicable` 不作为自动通过状态。确实不适用的变体须记录具体 Profile/场景、理由和复核人；若因此删除 v1 必需来源或行为，则是范围变更，不能由实施者静默豁免。

### 证据层级

| 代码 | 必需的可观察证据 | 不能替代什么 |
|---|---|---|
| C 产品行为 | 对运行中的公开命令/接口施加输入，核对持久状态、真实账本和实际被接收/拒绝的副作用；外部报告可控注入 | 不替代真实来源身份/计费资格 |
| U 工作台 | 真实页面操作、刷新/断线/过期命令及界面所对应快照/事件；安全内容渲染和认证结果 | 静态截图或 mock 页面不能证明后台行为 |
| P 本机执行 | 实际进程/进程树、文件边界、IPC/网络 canary、持久启动记录、真实终止及恢复轨迹 | mock supervisor、提示词和容器启动成功不能证明隔离/停止 |
| S 真实服务 | 已配置官方订阅或具体 API 通道的实际有界请求、接受配置、认证/计费/usage 与限制记录 | 假 provider 或另一 Profile 的成功不能继承 |
| G GitHub 远端 | 实际 repo/ref/PR/head、检查运行、响应丢失后的查询和外部修改证据 | 本地 bare remote 不替代 GitHub 行为 |

每份记录最少包含：`requirement_id/case_id/variant`、候选任务与实际 Issue/PR 链接、实现 commit、测试命令和固定输入、预期/实际结果、证据层级、日期、执行与复核者、结果及限制。涉及来源再加 Profile/runtime revision、模型/家族证据、OS/隔离、账户形态、配置摘要和观测范围；涉及候选/交付再加 repo/base/tree/commit、检查配置与 evidence digest、PR/head/CI 身份。只保存 secret_ref 或脱敏身份，不保存凭据。

## 8. GitHub gate 与最终完成审计

应区分两类 GitHub 证据：**Karajan 自身实现 PR 的检查/Review**，以及**Karajan 产品在测试仓库创建和核对 PR 的能力**。开发 PR 的 CI 全绿不能证明产品会安全交付；产品生成一个 PR 也不能证明 Karajan 当前实现 commit 已通过开发 gate。

最终实现交付须记录当前提交/PR/head、适用必需检查及 conclusion、独立 Review、未解决阻断问题和本清单版本。验收产物须能定位到同一实现 commit；合并/发布后若内容变化，补跑受影响检查。用户要求的 GitHub gate 由实际远端状态证实，不能仅记录本地测试退出码。

v1 只有在下列条件同时满足时才能标记完成：

1. FR01–FR20 与 AC01–AC06 的必需行为已实现，完整 A01–A26 的适用变体有可复查运行证据；D01–D09 无未说明的实现偏离。
2. 五来源逐项完成实际接入与所宣称角色/工具资格；缺配置、not_run、unsupported 的必需路径仍明确阻塞。不能把剩余来源移到“未来支持”后宣布原 PRD 完成。
3. 在实际机器和真实仓库得到 2–3 子任务、多来源、必需检查、独立 Review、真实唯一 PR 的结果；正常恢复、历史恢复、取消和远端副作用故障分别通过。
4. 当前 Karajan 实现 commit 的必需 GitHub checks/Review 有实际结论；产品 PR 的当前 head/base/CI/完成语义正确且没有自动 merge。
5. 本地访问、秘密边界、维护/保留与性能/效果量测均有结果。任何偏差明确列出影响与尚缺工作，不能以文档、预期表现或 Issue 数量代替结果。

开发仓库已经取得 [实际门禁证据](ci-gate-evidence.json)：双系统 CI 成功、临时失败用例使汇总 gate 失败并阻止合并、恢复后成功，以及已启用的无绕过主分支规则。该证据不替代产品的真实 PR 交付验收。后续填写证据时保留失败和重跑历史，记录结论变化原因；不覆盖或删除不利结果来使审计显示全绿。
