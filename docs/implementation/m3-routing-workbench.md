# M3：固定快照路由模拟工作台

本切片继续 [M3-01 #23](https://github.com/zhouy1017/Karajan/issues/23) 的规则模拟体验。真实 Web 接口直接调用已有 `evaluate_route`，输入是明确提供的任务、规则/授权与容量快照。它用于解释候选和排序，不把导入事实当作当前账户状态或派发授权。

## 接口与输入

已认证项目入口提供固定离线例子和无状态模拟。GET `rulebook/simulation-example` 返回与 CLI 固定输入相同的三份快照；POST `rulebook/simulate` 接受且只接受 `task`、`policy`、`capacity`。处理器先确认项目存在，随后只计算所提供的内容，不替换成数据库当前规则或额度，不写命令、发布、Run、预留或启动记录。

响应明确标记 `explicit_simulation`、`activation_allowed=false`、模型调用数 0，并包含同一个纯求解器的结果和完整输入绑定。接口不生成随机身份或使用当前时间补全快照，因此相同输入可重复比较。它没有应用操作，无需 If-Match 或幂等写入键；登录会话、Host、Origin、CSRF 和 64 KiB 请求体限制仍生效。重复 JSON 字段与非法输入返回结构化错误，秘密字段不回显。

## 工作台行为

规则编辑器可载入固定离线例子或完整快照文件，调整任务角色、就绪状态、复杂度、风险、路径、上下文与时长，再模拟当前编辑规则。只有 `policy.rulebook` 被替换；原模拟授权的 ceiling、已批准组与阶段保留。当前编辑新增模型或能力组，不会让演练自动扩大原批准范围。

页面展示事实来源、时间与未知值，以及命中规则、有效难度、服务返回的候选顺序、每个淘汰原因和排序分量。完整输入与报告可导出；输入或规则变化使旧结果失效。模拟不采用规则、不启动任务，不改变已发布版本。真实派发仍需要可信程序生成完整快照并接通统一准入。

## 验证范围

Windows 独立运行全部 Web 与路由测试 **137 passed / 11.60 秒**；WSL2 新 API 用例 **21 passed / 4.18 秒**。全仓 Ruff 与 90 个后端源文件 strict mypy 通过。测试预置真实本机 Run 和配额 Reservation，模拟前后项目、Run、容量三库的所有逻辑表逐行一致；固定 Profile 中绑定的本地模型接收器实际收到 0 次请求。现有应用未接入独立 Host 或现金账，证据没有将它们描述成已参与测试。

最终前端 **138 passed / 11.01 秒**，其中 48 项模拟交互覆盖输入导入、规则替换、冻结授权、候选顺序、过期响应和结果失效。独立 Spec 另外运行 10 项 HTTP 边界检查与原 21 项 API 用例；冻结 API 的独立 Standards 审查没有遗留问题。

审查实际修复了特殊标识 `__proto__` 导致页面渲染失败，以及导入 `1e400` 后被序列化为 `null` 的问题，保留原输入和失败/复验记录。不安全整数也会改变 Profile 身份摘要，现导入一律拒绝非有限数字和不安全整数；普通有限浮点沿用既有数值契约。候选按服务器 rank 展示，重复 JSON 字段及超过最终 64 KiB UTF-8 请求体的输入会在发送前拒绝。

真实浏览器加载已发布 v2 的固定例子，重复得到相同候选和三份输入摘要；T1 空组显示阻塞，T0 不产生候选，critical 风险将 T1 提升至 T3。任务或规则草稿变化后旧结果立即撤下；刷新后仍是原保存规则。前后项目/发布、Run 和容量快照完全一致。长规则摘要在实际窄屏观察中曾溢出，修复后完整换行。文件导入与过期响应由交互测试验证，不描述为浏览器实测。

实际记录见 [证据目录](../../examples/routing-workbench/README.md)。当前报告只证明固定快照模拟，不代表真实来源资格、旧 Run 显式采用或统一 F03/F05 准入通过；真实现金 API 调用数仍为零。GitHub 检查在提交后按实际结果记录。
