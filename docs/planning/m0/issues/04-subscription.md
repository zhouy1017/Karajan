# M0-04｜验证一个官方订阅执行器的协议与权限绑定

## 用户价值

平台能经官方执行端使用订阅，并明确表达模型确认、原生权限和配额的可见范围，不把订阅伪装成通用 API。

## 范围与演示

优先固定一个 Codex app-server 版本，检查公开协议并制作可重放夹具，演示“指定模型与范围→原生权限请求→有效裁决/迟到拒绝→结构化结果”。若该路径不满足契约，记录失败证据并提出 Claude 官方路径的替代探针；此票只要求完成一个订阅执行器的有界调查。

- 固定运行时版本和配置来源；记录 requested、accepted、provider_reported，不能从启动参数推断实际生效。
- 权限请求绑定 Attempt、fence、request/turn、授权 hash 和有效期。取消、换期或过期后的批准无效。
- 原范围内裁决不扩大 session 权限；不支持动态绑定时明确 reject/block，不能静默放行。
- 检查关闭内部模型切换、跨账户/收费 fallback、额外委派的实际控制点；不可控制即不合格或能力受限。
- 将可见用量/额度、估算和 unknown 分开。官方登录仍由官方运行时保管，不导出订阅凭据作为 broker key。

## 验收标准

- [ ] 固定版本的协议字段、事件顺序、错误分类及来源记录可复核；夹具入口可以重放成功、拒绝和未知分支。
- [ ] 错误或迟到的权限批准不能恢复取消的执行，也不能授予更宽的 turn/session 权限。
- [ ] 参数被忽略、模型反馈缺失、隐藏 fallback 无法排除时报告明确失败/未知，不标记相应能力 passed。
- [ ] 报告列出真实登录、实际推理、实际文件工具和取消仍须验证的用例。
- [ ] 只凭协议/夹具完成时，live 结果保持 not_run；形成可供 M0-06、M0-07 使用的最小适配入口和复现说明。

## 验证与边界

可以离线完成协议与适配入口；实际账号测试统一在 M0-07 有明确配置后进行。此票不建设所有订阅适配器，不要求精确配额接口，不执行真实 PR。

关联 FR02、FR07、FR16；A12、A23 的订阅协议部分。通过夹具不代表原生工具沙箱已经安全验收。
