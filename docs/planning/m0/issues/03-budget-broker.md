# M0-03｜验证资源切片、逐调用准入与发送未知

## 用户价值

并发请求和网络故障不会重复分配同一预算，也不会因缺少应答而把可能已消费的金额当作可用余额。

## 范围与演示

用最小 SQLite 账本、窄推理 broker 和假 provider，演示同一父预算下多个请求竞争、一个被拒绝，以及发送后崩溃导致占用保留。先固定一种 API 协议，不建设全部路由系统。

- 父预留、子调用切片和实际结算避免重复扣算；现金按原币分别约束。
- 发送前持久化 send intent；请求、上界、价格版本和可观察回执可追溯。
- send_unknown 保留上界，先核对，不能自动释放或不计成本重发。
- broker receipt_id 与可验证 logical_call_id 分离；无逻辑 ID 时每次传输请求重新准入，不按 prompt 正文去重。
- 重复用量报告幂等记账；价格过期/未知或无法覆盖全部收费项时拒绝 bounded_calls 资格。

## 验收标准

- [ ] 并发请求的父预算占用、子切片及结算总量始终可核对；拒绝请求在假 provider 的接收计数为零。
- [ ] 发送前、发送后未记回执、记回执后崩溃均可重现；unknown 不导致余额恢复或盲目重发。
- [ ] 重复结算不重复扣账；迟到的真实费用不会因 Attempt 终态而被忽略。
- [ ] 无 logical_call_id 的重试作为新准入处理；有 ID 时也只有验证过的语义才允许幂等，不假设 provider 支持幂等请求。
- [ ] 不同币种预算不混算；价格版本失效和收费上界缺项时不发送硬预算请求。
- [ ] 输出账本快照、假 provider 收包记录与故障报告，可从外部观察重算结论。

## 验证与边界

全部使用假金额和本地 provider。此票只证明可控调用的计量原语，不证明真实厂商价格完整或现金硬上限。真实计费边界在 M0-07 验收。

不做完整配额窗口、Commander 保留量、Rulebook 排序、FX 汇率或 Web。关联 FR10；A19、A26 的账本与请求部分。
