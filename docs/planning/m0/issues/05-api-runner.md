# M0-05｜验证固定 API 执行器的工具循环和请求通路

## 用户价值

API 模型能完成工具交互，同时平台可以知道每个模型请求去了哪里，避免执行器内部重试或换源绕过资源规则。

## 范围与演示

固定一个 OpenCode server 版本及一种拟采用的 provider 协议，用本地假 provider 驱动“工具调用→工具结果→最终输出”，捕获实际网络请求。复用执行器的工具循环，不重写通用 Agent 框架。

- 固定模型、endpoint 和允许工具；探测关闭/约束内部自动 fallback、额外委派、SDK retry 的真实设置。
- 管理 API 与模型请求通路分离；请求能够被窄 broker 接管，不能由工具直接访问管理接口。
- 实测请求身份、重试次数、logical_call_id 是否存在及其含义；缺 ID 的请求按新调用处理。
- 取消后记录是否还有请求；区分客户端中止与 provider 端停止。

## 验收标准

- [ ] 假 provider 捕获完整工具循环，请求只发送到指定通路与模型；输出包含可复查的请求/事件轨迹。
- [ ] 注入断线、429 和超时，真实传输重试次数可观察，不能仅依赖配置声明。
- [ ] 无法关闭且无法纳入固定 Profile、逐请求准入与计账的隐藏请求/fallback 被明确标记不合格；不得声称满足逐调用现金控制。可观察且受同一准入控制的 SDK retry 不因此被误拒绝。
- [ ] 模型配置、工具权限或网络路径被修改时，探针拒绝或报告不符，不接受为原 Profile 成功。
- [ ] 取消结果有事实与限制说明；没有真实 provider 证据时不声称远端停止或费用已结清。
- [ ] 交付一个最小适配入口、固定版本说明和不含真实密钥的可重放样例。

## 验证与边界

假 provider 不需要 [M0-03 #4](https://github.com/zhouy1017/Karajan/issues/4) 的完整账本；两者在 M0-07 组合。此票不实现全部协议或 DeepSeek/Go/第三方的完整接入；各服务认证、计费与模型能力须单独资格验收。

关联 FR02、FR07、FR10；A12、A26 的 API 执行器部分。结果不等同于真实 Profile 合格。
