# M0-02｜验证 RunnerHost 启动、取消与失联核对

## 用户价值

平台重启或取消任务后，用户不会因为应答丢失而多启动一个执行者，也不会把仍运行的子进程误判为已停止。

## 范围与演示

实现最小持久启动登记和一个可创建子进程、延迟结果、模拟丢应答的假执行器。在拟采用的 Windows/WSL2 执行路径演示“启动时崩溃→重启核对→只有一个受控执行”，以及“取消→确认进程树事实”。

- 持久化 accept intent，启动前校验当前 activation、授权、暂停状态和 fence；实际 spawn 后记录可核对回执。
- 模拟 accept、spawn、ACK 前后崩溃及重复 start。spawn_unknown 先核对，不能盲目重放。
- 将业务结果、进程退出、远端推理停止和计费结算分开表达。
- 恢复核对包含业务已结束但物理执行或消费尚未关闭的 Attempt。
- 旧 fence 的结果不能被接纳；迟到消费事实仍保留。

## 验收标准

- [ ] 固定种子的故障脚本逐个覆盖上述崩溃点；执行登记与实际子进程计数可供检查。
- [ ] 同一 start_key 重放不产生第二个进程；无法证明原执行状态时返回核对中并禁止再次 spawn，不能仅靠拒绝旧结果掩盖重复执行与消费。
- [ ] 取消后的子进程实测退出或被确认隔离；仅收到取消 ACK 不算停止证明。
- [ ] 业务成功但子进程仍存活的夹具，重启后仍出现在核对列表。
- [ ] 迟到结果被拒绝，已发生消费/退出事实可继续追加，不复活任务。
- [ ] 报告区分已测 Windows/WSL2 路径与 not_run 环境；本地进程停止不声称远端模型停止或退款。

## 验证与边界

使用真实操作系统进程和假模型，不使用订阅/API 账户。通过窄执行入口和进程清单验证；不实现完整协调器、Run 恢复、Web 或所有隔离策略。

关联需求：FR15、FR18；A09、A10 的 RunnerHost 原语部分。真实运行时取消能力在 M0-07 组合验证。
