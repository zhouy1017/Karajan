# M0-01｜建立可执行契约与资格报告格式

## 用户价值

给定一个执行配置和探针结果，维护者能明确知道它支持什么、哪些能力未测、为什么不能派发。后续探针使用同一组输入和报告，不用先搭完整平台。

## 范围与演示

提供一个离线可运行的窄入口：读取 Profile、Attempt Manifest 和脚本事件，校验后输出机器可读报告及简短摘要。演示一个合格夹具和至少一个被拒绝的夹具。

- 定义本轮探针必需的配置身份、版本、角色、固定模型/通道、授权范围、Attempt/fence、预算引用和能力要求。
- 区分 requested、accepted、provider_reported、unknown；缺少确认不能推断模型或参数已生效。
- 区分 Attempt 级准入与可观察的逐模型调用；订阅内部不可见调用明确标记覆盖范围。
- 每个 case 记录运行时版本、Profile revision、OS/隔离、输入、观测、证据引用、日期和限制。
- 结果枚举为 passed、failed、not_run、unsupported；报告整体不得把后三者折算为 passed。

## 验收标准

- [ ] 一个命令可运行合法和非法夹具，输出稳定的字段和原因码；非法输入不会启动外部进程或模型请求。
- [ ] 未配置模型、认证引用、必要权限或能力时，报告明确指出缺项，不生成“已启用”配置。
- [ ] requested 与实际反馈不同、反馈缺失、事件重复或身份不匹配均有可观察结果。
- [ ] 纯离线夹具与真实环境证据分开；报告不能将 fixture_pass 解释为 live_qualified。
- [ ] 报告示例不含真实密钥；有简短运行说明和供后续探针复用的输入输出样例。

## 验证与边界

以入口的输入、输出和外部副作用计数验收，不只检查内部函数调用。测试工具可以轻量；本票不建设业务数据库、Web、完整 DAG、Rulebook 或所有适配器。

关联需求：FR02、FR07；A12 的契约表达部分。完成本票仅说明探针基础可用，不代表任何服务已合格。

## 依赖

无。首个可开始的 M0 主线任务，全部验收可离线完成。
