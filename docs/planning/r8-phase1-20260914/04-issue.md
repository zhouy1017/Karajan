# R8-P1-04：授权角色调度命令、动态任务图与完整待执行队列

## 问题与结果

基于已加载部署和明确的初始运行授权，建立新的版本化Workflow运行控制面。获授权调度主体提交结构化决定后，范围内立即成为持久任务图/待执行工作；支持不同任务数量、重叠grant竞争、扩展封口和资源等待，不回退到旧100任务或固定三角色协议。

## 依赖与范围

依赖03；依据architecture/11及FR26/27、RS-AC的C/P控制面子范围。新增workflow-runs/scheduling模块及受认证的管理/读回HTTP，复用03已加载定义句柄；受控角色命令接口绑定可信执行身份/能力。可借鉴既有storage、Run/Capacity的事务和幂等模式，避免把新图塞入旧固定Plan模型。

## 验收条件

- [ ] AC1：从active且本进程加载就绪的部署、具体输入与显式授权创建持久Workflow运行记录；冻结部署/初始输入/授权摘要，另存当前图引用。拒绝未就绪/跨项目/旧批准；重传不多建运行。明确与旧Run schema兼容边界，不伪造旧业务已执行。
- [ ] AC2：SchedulerGrant记录主体、范围、动作、固定角色/模型/工具/路径集合、父授权和资源政策；子授权只取父授权子集，默认不能隐含转授权。启用委派时有明确最大深度或等价有界链、当前任期/到期及父撤销传播，共享父预算归属，不复制额度。管理授权入口由认证用户创建真实角色实例/受信协议消费者身份，并由服务端签发或绑定窄作用域命令凭证；测试经该入口一路提交，不直接插库或自报运行中Attempt。凭证按Run/grant/角色实例认证，模型请求自报ExecutionRef、角色名或传user=true不能获得权限；管理授权与角色命令接口分开。未发模型调用时标为受信协议消费者C/P输入，不冒充模型执行身份或S资格。
- [ ] AC3：有效SchedulingDecision经过身份/grant/动作/图版本/输入输出/无环/完成义务校验，在同一短事务提交新TaskGraphRevision、决定回执和完整待执行任务；范围内无需逐任务新批准。幂等键重传不扩出重复节点，同键异载荷拒绝，过期/撤销grant拒绝。
- [ ] AC4：两个有效grant可明确覆盖重叠范围；图revision/CAS防覆盖并保留冲突回执。冻结已领取工作项的输入/绑定；后续图形成新revision，保留被替代节点、失败、消费与既有完成义务。不得删失败任务、改optional或改名消除已承诺结果；真实Attempt冻结留待物理执行接线验收。
- [ ] AC5：ExpansionSet open时不提前汇合；seal固定成员revision并校验必需义务。图可包含1/3/7及超过100项任务，均完整持久/分页读回，无默认Agent/任务总数。资源等待由显式政策/可信资源观察输入判定，缺容量保留任务，释放后成为ready；状态刷新和队列唤醒不调用模型。
- [ ] AC6：提供可信执行消费者读取ready工作并幂等领取的接口，记录task/graph/grant与声明的写区互斥；同区写任务不同时领取，独立写区按实际政策可领取，重复claim/重启不重复创建工作。它是执行准入交接点，不能把claim或模型自述标成物理started/completed；未知执行不自动释放占用。
- [ ] AC7：真实SQLite/HTTP/文件集成测试覆盖冻结部署消费、授权内自动接受、越权/撤销、CAS/重传/重启、sealed汇合、义务不可抹除、101+任务完整排队和同写区互斥。更新可复现示例及证据；Ruff/mypy/快速门通过。
