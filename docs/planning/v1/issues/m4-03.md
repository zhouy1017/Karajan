# M4-03｜真实远端 gate、全量证据与 v1 出口

Parent：[PRD v1 #1](https://github.com/zhouy1017/Karajan/issues/1)

## 目标

五来源、真实仓库、远端 gate 与全部需求审计闭合。

## 本轮执行边界

用户已授权完整设计、拆票、实现和 GitHub gate；**本轮不执行任何现金 API 调用，真实 API 验收保持 not_run**。禁止订阅/额度错误后转额外余额或现金后备。开发、安装本地依赖、假 provider、协议回放、真实本机进程/文件测试和不产生现金模型请求的 GitHub 工作可在已授权范围内继续；缺具体账户、模型、金额、仓库或能力事实时，只阻塞依赖它的真实路径。

本票的 Blocked by 是最终验收/能力启用 gate，不禁止独立离线工作。离线实现可以完成并单独验收其实际覆盖行为；真实资格或完整端到端条件未满足时保持未勾选/not_run，不据此宣称该能力或阶段全通过。已有配置授权不重复询问，空值不解释成无限权限或预算。

## Scope

在用户指定真实仓库完成 2–3 子任务需求，跨来源协作并取得实际 GitHub PR；故障注入交付网络响应、外部 head/base 和取消，完成全部需求/来源/维护及性能审计。此票是验收和必要缺口修复的有界收尾，不承担未实现的大功能。

提供固定实现 commit、真实测试仓库/目标分支/需求/检查命令、独立 GitHub 交付身份与当前 CI 配置、各来源资格及全量审计记录。缺少现金来源真实证据时保留最终 gate 缺口。

五来源分别是 ChatGPT 官方订阅、Claude 官方订阅、DeepSeek 官方 API、OpenCode Go 订阅通道和用户指定第三方 API。每项至少有明确可用角色及对应真实资格，不能用相同 runner/协议或模型别名继承通过。全量审计逐行记录 FR01–FR20、PRD-AC01–06、A01–A26、D01–D09 与非功能要求；本地审计文件为 `docs/implementation/requirement-coverage.md`。

## 接口与输入契约

下列契约未冻结时先按现有设计与假实现开展工作；最终集成绑定精确版本和能力证据。仅记录 Fxx 编号、字段名或支持布尔值不足以启用能力。

- F01（来自 M0-01）：冻结版本化 Execution Profile、Attempt Manifest、事件/资格报告字段与稳定 reason code；不能由未认识的字段推导权限。
- F02（来自 M0-02）：冻结持久启动身份/start_key、启动许可 activation、inspect/cancel 及 running/exited/unknown 的事实边界；未知启动不能重新 spawn。
- F03（来自 M0-03）：冻结原币预算、父子调用切片、receipt 与可选 logical ID、send intent/send_unknown 和结算协议；无法证明未发送的占用不能释放。
- F04（来自 M0-04/05/06）：冻结各 adapter 实际接受的模型/原生设置、单次权限答复和工具/进程/网络隔离声明，包含不可用或未覆盖路径。
- F05（来自 M0-07 及后续来源资格）：冻结精确版本/环境下真实合格的 Profile、允许角色/能力和执行接口；离线 fixture 不让 Profile 自动获得 enabled 或 bounded_calls。

## 验收标准

- [ ] 真实 GitHub 上验证 push/PR 已成功却应答丢失、重复 revision、外部更新、push 后取消、远端 CI 对当前 commit 的关联；无重复 PR/越权覆盖/自动 merge。
- [ ] 默认完成和预设 CI gate 分别通过。
- [ ] 默认在必需本地检查与独立 Review 通过且 PR 创建已确认后完成，CI 单列；预设 CI gate 的 Run 等待当前 commit 的该条件。两者均不把 PR 创建显示为 CI 或合并成功，不自动 merge。
- [ ] 保存最终实现 commit、必需 CI checks/conclusion、独立 Review、候选/PR/head 与测试证据的对应关系；旧 commit 的 green 不授权新 head。
- [ ] FR01–FR20、PRD-AC01–06、A01–A26、D01–D09 的适用行都有真实或正确层级的运行证据；五来源各自合格范围明确，必需角色/工具能力无缺口。
- [ ] not_run/unsupported/缺账号不能静默计为 v1 完成。
- [ ] 模型若失败须正确停止且记录，不伪造成功率；记录真实连续运行、修复/等待/费用/未知比例及本地性能测量。
- [ ] 在固定机器/样本/负载下量测普通本地命令/快照 p95 小于 1 秒、正常持久事件 2 秒内到 UI；排除模型、外部网络和检查执行时间，并在 2 writer 加必要 Review/规划竞争时验证工作台可操作。实测偏差明确登记，目标值不作为结果。
- [ ] 验收记录逐项标明真实或 fake 的覆盖；本轮现金 API 实际请求数为零，相关真实验收保持 not_run，未执行项不勾选。
- [ ] 提交实现 commit/PR、可运行入口、固定输入与执行命令、实际结果/副作用证据及限制；失败与重跑历史保留，不能只提交文档或 fixture 宣称通过。

## 离线与真实验证的边界

**本轮可做：**先自动汇集每项需求、版本、证据层级和缺口；使用本地真实进程/fake provider/remote 准备全故障脚本和性能量测，不做现金 API 请求。

**不足与真实 gate：**必须分别证明 Karajan 开发 PR 当前 commit 的 GitHub checks/Review，以及产品在真实测试仓库的 ref/PR/head/CI 行为。fake 模型或本地 remote 不能替代真实跨来源代码任务和 GitHub；所有现金 API 资格本轮 not_run，因此其必需缺口仍阻止 v1 最终完成。

**必须保存：**保存 FR/AC/A/D 逐行审计、五来源能力表、当前实现 commit、开发 PR checks/Review、产品 PR/head/base/CI、真实运行指标及未执行/失败历史。

证据应绑定实现 commit、case/variant、Profile/runtime revision（如适用）、OS/隔离、日期和结果；只保存 secret_ref 与脱敏身份，不把实际凭据、原始认证材料或秘密写入 Issue/日志/导出。能力结果区分 passed、failed、not_run、unsupported，后两者不计为通过。
