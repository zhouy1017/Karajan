# Karajan v1 全量实施任务

日期：2026-09-05。依据：[PRD v1](../prd/karajan-v1.md)、[已确认架构](../architecture/README.md)、[验收矩阵](../architecture/05-build-and-validation.md)和[需求覆盖审计](../implementation/requirement-coverage.md)。

用户已将目标扩展为整个 PRD 的设计、拆票、实现与 GitHub gate。M1–M4 共 20 个任务已发布为 GitHub Issues #11–#30；原生父子关系和 37 条依赖边已逐项读回核对，实际链接见[发布记录](v1/github-publication.json)。任务发布不代表功能已实现或验收通过；实施证据由覆盖清单独立记录。

## 1. 执行与完成规则

- 保留已发布的 8 个 M0 任务，新增 20 个 M1–M4 纵向任务。每票交付可观察行为、适用接口/界面与证据，不按数据库、后端、前端分别创建空骨架票。
- `Blocked by` 表示该票最终验收依赖的产物或能力。离线设计、接口类型和假环境开发可以提前做；尚未冻结的接口使用下表的 `待冻结 Fxx` 标记，不能把 stub 当作真实资格。
- 第一条真实调用就经过合格 Profile、有效授权、固定规则/批准集合、所有适用资源约束、原币硬预算、有限 unknown 模式和所需隔离。规划、顾问、检查中的模型调用也遵守同一底线。
- M1 形成候选时即要求必需检查与独立 Review，包含最小人工 Commander 交接。M3 扩展规则编辑、资源平衡、自动 Worker/Reviewer 换源与完整交接工作台，不补做先前缺失的执行底线。
- 真实账号、endpoint/model、预算数值、测试仓库及权限仍是执行输入。用户的整体工作授权已经存在，不反复询问已确定选择；缺少具体参数时只阻塞依赖该参数的真实路径，不停止其余开发，也不把空预算解释成无限额度。
- 这些任务的发布初始状态统一为 `未实现 / not_run`。测试夹具、编译通过、文档与 Issue 关闭均不能代替产品或真实环境通过。具体完成审计采用 [覆盖清单](../implementation/requirement-coverage.md)。

## 4. M1：安全的第一条串行产品流程

### M1-01｜可信项目、配置与认证入口

- **目标与 scope：**通过最小 Web/API 登记项目、基准与目标分支，导入/预览固定 Rulebook、Profile 资格引用、规划/Run 预算及有限 unknown 设置。实现命令幂等、版本冲突、本地会话、Host/Origin/CSRF、受认证的读取和产物入口；不在登记时启动模型。控制端与凭据引用保持在执行环境之外。
- **关键 AC：**有效项目保存可解析身份/base；越界路径、未知基准、坏共享关系/币种、缺预算、未知必需能力不能启用执行。重复同键同载荷返回原结果，同键异载荷冲突；未认证 API/SSE/产物读取和跨站写入被拒绝。使用假秘密实测不进入日志/导出。固定规则已具备风险下限、批准集合及硬条件校验。
- **Blocked by：**M0-03；待冻结 F01、F03。无真实调用即可完成此入口，不能由此把 Profile 标为真实合格。
- **关联：**FR01、FR02、FR04、FR06、FR08–FR10、FR16、FR17；PRD-AC01；A11、A12、A13、A26 的入口子集。覆盖本地认证与秘密处理非功能要求。

### M1-02｜有界规划、确认和最小人工交接

- **目标与 scope：**从需求进入主 Commander 规划；在已配置预算内征求顾问；校验结构化计划、T0、角色、范围和任务图，显示并批准具体 plan/authorization hash。包含简洁但可操作的 Commander 交接提案与确认/拒绝入口。
- **关键 AC：**规划和顾问均经真实合格 Profile 的授权/资源准入，确认实施前不能写仓库代码；顾问和旧 term 无计划提交权。批准旧版本无效。交接展示检查点、指定候选和资源影响；不答复/拒绝不启动替任，有效确认仅激活指定新 term，迟到确认拒绝。已批准且不依赖新决定的工作不被全局暂停。
- **Blocked by：**M1-01、M0-07；待冻结 F02、F04、F05。可先用 fake Commander 实现全部动作，但真实规划与交接验收必须补齐真实调用与来源/预算记录。
- **关联：**FR03、FR04、FR07、FR08–FR10、FR12；PRD-AC02、PRD-AC04；A02 的规划协作子集、A11。D02、D03、D06、D07 从此票开始执行。

### M1-03｜串行执行、冻结候选与独立质量门

- **目标与 scope：**已确认计划激活一个 Worker，经 RunnerHost 与资源入口运行，在独立副本形成不可变候选，再运行可信检查和独立 Reviewer。贯通最小状态/outbox/inbox、当前权限裁决、暂停/取消与候选/证据详情。必要的次数、时间、预算和根链计数从此时生效；自动修复扩展留给 M3-04。
- **关键 AC：**冻结 Profile/授权和 activation 后才启动；重复 start/失联不会再派第二 writer。原生权限取消后迟到答复无效，未知停止保持核对。Collector 不加载候选的高权限 Git hooks/config。实际测试失败、缺日志、Review 不确定或无合格 Reviewer不能可交付；T1/T2 新上下文、T3 不同家族。修改候选/base/检查条件使旧证据失效。跨至少两种已合格来源得到同一内容身份的候选与独立审查。
- **Blocked by：**M1-02；使用已冻结 F01–F05。源码实现与本地故障集成需齐备；真实 Worker/Reviewer 和所启用工具均须有对应资格。
- **关联：**FR07、FR10、FR13–FR16、FR18；A01 串行部分、A09、A10、A12–A16、A18、A19、A23 的首条产品路径；D01、D05、D06、D09。

### M1-04｜独立交付、同一 PR 与完成语义

- **目标与 scope：**从可交付候选进入独立凭据/IPC 域，持久化每步 intent/activation，条件更新受管分支并创建/更新同一 Run 的 PR。Web 分列本地 gate、PR、实际 head、远端 CI 和合并状态。
- **关键 AC：**Worker/Reviewer/检查均无法 push 或借交付端点创建 PR。每步重查暂停/取消、授权、候选、证据与 expected head；push 成功后的取消阻止尚未激活的 PR 创建。响应丢失先查指定对象，未核清前禁止下一 revision 发布；外部 head 不覆盖。真实 GitHub 上验证默认完成与预设 CI gate 两种模式，均不自动 merge。
- **Blocked by：**M1-03；还需实际授权的测试 remote/分支、独立交付身份与可触发检查配置。假 remote 可先证明协议，最终验收必须有真实远端对象。
- **关联：**FR19、FR20；PRD-AC06；A01 串行完成、A14–A17。D05、D09；M4-03 扩大远端故障与最终 gate 复测，不延后本票的安全语义。

### M1-05｜计划修订与成果复用

- **目标与 scope：**在已有候选的 Run 中提出、预览并批准 v2；显示任务/权限/依赖影响，明确 `plan_tasks` 成员，保留有效 task revision 与证据，生成受影响的新版本及后续义务。
- **关键 AC：**A 已完成、只改 B 的 v2 复用 A，旧 B 迟到不能满足 v2；输入变化沿依赖使证据失效。新来源/预算/权限不能借复用或规则发布自动获得。被移除任务不继续阻塞当前计划完成，旧进程与消费仍被核对。确认请求与旧版本结果竞态有可观察拒绝。
- **Blocked by：**M1-03；无需等待并行调度才能用串行 A/B 验证版本语义。
- **关联：**FR04、FR05、FR13、FR15；A11、A16、A22。

### M1-06｜可恢复运行视图与当前有效操作

- **目标与 scope：**贯通 Run/Task/Attempt、路由原因、资源置信、候选、证据、PR 和可处理阻塞；使用一致快照加持久事件，提供暂停、取消、恢复/核对、重试及有效交接入口。补齐 M1 用户从提交到 PR 的连续体验。
- **关键 AC：**页面刷新、SSE 中断/重复/游标过期及后端重启后显示同一事实；过期动作拒绝且不修改状态。没有证据时不显示精确剩余任务数/消费余额。暂停仅停止新派发和新交付，取消状态反映实际停止范围；普通日志流不能挤掉状态事件。所有读取保持认证，不可信日志/Markdown/diff 不执行脚本。
- **Blocked by：**M1-04、M1-05；产品演示覆盖 PRD-AC01/02/04/05/06，真实 M1 出口必须包含两来源、检查/Review 与 GitHub PR。
- **关联：**FR15–FR20；PRD-AC05；A09、A10、A17、A20、A23 的 M1 组合路径；运行视图与本地访问非功能要求。

## 5. M2：并行和五来源逐项资格

### M2-01｜2–3 子任务并行与组合验证

- **目标与 scope：**实现依赖驱动的派发与每项目默认 2 writer、独立工作区/缓存写入、前置候选读取、固定顺序集成及冲突阻塞/有界处理；把组合候选接入已存在的验证与交付链。
- **关键 AC：**真实小功能拆成 2–3 项并行完成；任务不共享可写 `.git` 或越界修改。依赖不足不提前执行，冲突不默选一侧，最终候选重新跑全部必需 gate；Plan v2 与迟到并行结果仍遵守成员/证据规则。Commander、Worker、Reviewer 的选路不受同一项目品牌绑定。
- **Blocked by：**M1-04、M1-05。不等待其余三类来源都接入才能开发；M2 最终来源出口仍需要以下五票。
- **关联：**FR05、FR07、FR13、FR14；A01、A02、A13、A16、A22。

五张来源票共享记录格式，不共享 passed 结论。实际版本、OS/隔离、账户形态、模型家族、认证/计费、允许角色、参数接受证据、工具、启动/取消/核对、消费覆盖范围均分别留证。M0 已验证的同一版本/环境证据可以引用，并补产品角色集成；任何变化均重新验证相关项。

### M2-02｜ChatGPT 订阅产品接入

- **目标与 scope：**将用户的 ChatGPT 订阅经固定官方 Codex 执行端登记为可选择 Profile，完成至少一个所宣称角色的产品任务和必要工具资格；单列登录可用与自主仓库工具可用。
- **关键 AC：**官方登录和实际接受的模型/原生设置可追溯，不因环境 key/错误静默转现金。未知订阅额度只走获准有限模式；原生权限、工具/子进程、取消后迟到和恢复能按声明处理。真实调用与产品候选/规划/Review 输出具备关联；不据协议字段存在填写精确费用。
- **Blocked by：**M1-03；待冻结该 Profile 的 F04/F05 扩展，需具体官方登录、版本/模型、订阅占用边界与隔离配置。
- **关联：**FR02、FR07、FR09、FR10、FR15、FR16；A02、A09、A10、A12–A14、A23 的 ChatGPT Profile 用例。

### M2-03｜Claude 订阅产品接入

- **目标与 scope：**固定官方 Claude 执行端及实际 Windows/WSL2 路径，以用户订阅身份接入产品，不以 Codex 的资格推断 Claude 的能力。
- **关键 AC：**逐项验证认证/现金优先级、原生参数、会话/调用可见范围与固定 Profile。Bash、内置文件工具、子进程及启用的 MCP/hooks 各有权限证据；WSL 互操作出口受约束，无可证明动态单次批准时拒绝旧请求并使用新 Attempt。真实角色任务、停止/核对与 unknown 消费均留证。
- **Blocked by：**M1-03；待冻结该 Profile 的 F04/F05 扩展，需官方登录、模型/版本、有限订阅配置及目标执行环境。
- **关联：**FR02、FR07、FR09、FR10、FR15、FR16；A02、A09、A10、A12–A14、A23 的 Claude Profile 用例。

### M2-04｜DeepSeek 官方 API 产品接入

- **目标与 scope：**经已受控 API runner/broker 对接固定 DeepSeek 官方 endpoint、模型及计费身份，注册本通道独立 Profile 与价格事实。
- **关键 AC：**真实工具循环所有收费请求都受逐次准入，实际参数/通道与请求记录一致；重试、隐藏 fallback、输出及其他收费项不能绕过上界。拒绝请求不发出，未知发送不恢复余额；在实际计费单位下证明所声称的预算能力。缺上界或证据时 Profile 不具备硬预算资格。
- **Blocked by：**M1-03；需具体 endpoint/model、secret_ref、价格/收费上界及原币额度。M0 若已采用同一 Profile，只补未覆盖的产品路径与新版本差异。
- **关联：**FR02、FR07、FR10、FR15；A02、A09、A10、A12–A14、A19、A26 的 DeepSeek Profile 用例。

### M2-05｜OpenCode Go 通道产品接入

- **目标与 scope：**登记用户实际 Go 订阅通道、允许模型及账户共享关系，经受控 API runner 接入；把服务计量窗口和额外现金通道分别表示。
- **关键 AC：**真实认证/参数和所有模型请求出口可核对；服务计量金额不混作 API 现金余额。逐项记录可见窗口与未知部分，验证额度错误及潜在现金 fallback 的阻止行为。Go 不是因使用同一个 runner 就继承 DeepSeek 或第三方的计费资格。
- **Blocked by：**M1-03；需实际 Go 账户/档位、模型、允许计费路径和有限使用配置，待冻结通道事实。不能用普通 API key 的成功替代订阅通道证据。
- **关联：**FR02、FR07–FR10、FR15；A02、A05–A07、A12–A14、A19、A26 的 Go Profile/计量用例。

### M2-06｜指定第三方 API 产品接入

- **目标与 scope：**接入用户指定的一家第三方 endpoint/model/计费主体，校验协议差异、数据去向与可接受参数，声明实际而非猜测的模型家族/能力。
- **关键 AC：**实际请求只能到登记 endpoint，不能由输入改 URL/现金路径；模型别名、自报身份和可核查身份区分。逐调用预算、重试/未知、工具循环及隔离按该通道重新验收；家族未知不能满足 T3 不同家族 Review。缺必需能力明确阻塞，不删除第三方 v1 目标。
- **Blocked by：**M1-03；需用户指定厂商、endpoint、model、secret_ref、计费上界及原币测试限额。未指定时可先做协议/拒绝开发，真实资格保持 not_run。
- **关联：**FR02、FR07、FR10、FR14–FR16；A02、A09、A10、A12–A15、A19、A23、A26 的第三方 Profile 用例。

## 6. M3：资源与换源完整产品化

### M3-01｜Rulebook 编辑、模拟和版本发布

- **目标与 scope：**将 M1 固定规则扩展为可编辑矩阵、能力组、排序与升级集合，支持预览、无副作用模拟、差异和发布；Run 显式重评估但保留原授权约束。
- **关键 AC：**同快照模拟候选/顺序/排除原因一致且不建预留、不调用模型。T0 不实现，trusted risk floor 派生正确；歧义/缺规则阻塞，unknown 不当零成本。新增组成员或更宽规则不能进旧 Run；过期 plan/hash 或导入预览不能应用。跨币种排序无参考快照时按规定跳过该排序项。
- **Blocked by：**M1-05；与 M3-02/03 的状态快照接口可并行冻结，不依赖其完整 UI。
- **关联：**FR04、FR06、FR07、FR08、FR10；PRD-AC03；A08、A11、A25、A26 的规则/排序部分。

### M3-02｜共享池、多窗口、观察和保护量

- **目标与 scope：**将 M1 有限准入扩展为多账户/多 Run 的共享服务池和本地 allowance、多窗口观察、外部消费、人工校准、保留量设置及公平调度。资源工作台显示来源、时间、覆盖及估算/未知。
- **关键 AC：**两个 key/模型争用同池时所有约束原子成功或回滚；Worker/顾问不能借主 Commander 保护量。两 Run 固定不同 Rulebook 仍使用当前 CapacityPolicy；改保护值不释放旧在途消费。外部/重复/延迟报告和短窗口重置不能双算实耗或绕过周/月池；缺有限 unknown 参数拒绝。一个阻塞任务不挡住独立任务。
- **Blocked by：**M1-03。服务额度语义需引用各来源证据；可先用可控报告完成产品行为，真实来源无法报告之处仍展示 unknown。
- **关联：**FR08、FR09、FR17；A03–A06、A25；D03、D06。

### M3-03｜逐调用消费、原币预算与未知核对

- **目标与 scope：**把 M0/M1 的现金底线完善为产品级父子切片、价格版本、原币账目、对账/调整与调用追踪；包含规划、顾问、失败、Review、重试、修复全部成本。
- **关键 AC：**并发切片不双算父子，send intent 前/后崩溃具有不同处理；send_unknown 保留上界，无法证明未发送不释放或盲重发。SDK 无稳定 logical ID 每次接收重新准入，不按正文去重。USD/CNY 等原币限额各自约束；失效价格/未知收费项不发送硬预算请求。真实 API 请求日志与可见用量对账，订阅按 Attempt 明示覆盖范围。
- **Blocked by：**M1-03。真实通道价格/上界分别绑定 Profile；不因通用账本测试通过就给所有来源 bounded_calls。
- **关联：**FR03、FR08–FR10、FR17；A05、A18、A19、A26；D06。

### M3-04｜自动换源、质量升级和累计修复

- **目标与 scope：**按错误分类自动处理 Worker/Reviewer 的退避、合格集合内换源、预授权质量 stage 与 repair chain；实现每 Run 默认 2 轮质量修复、每根任务默认 2 次基础设施重试及统一预算/时间限制。
- **关键 AC：**429 分清拥塞/耗尽/未知，已知耗尽不反复探测；旧执行实际停止或隔离且消费占账后才能换新 Attempt/工作区。换源不降低风险/验收、不借未获准现金。多个必需检查同批失败只计一轮；新 repair Task、计划修订、换源和重启不重置累计次数/消费。无合格者等待，Commander 从不走此自动替任入口。
- **Blocked by：**M2-01、M3-01、M3-02、M3-03；真实自动换源验收至少需要两个对应角色的已合格 Profile，具体由 M0/M2 证据选择。
- **关联：**FR06、FR10、FR11、FR13–FR15；A07、A08、A10、A15、A18、A24；D04、D05、D09。

### M3-05｜完整人工 Commander 交接工作台

- **目标与 scope：**在 M1 已可操作的交接基础上提供候选资格/费用比较、材料检查、当前 term、决定历史与独立任务继续情况；与完整规则/资源视图联动。
- **关键 AC：**每次换人都展示具体方案并由用户决定；不答复/拒绝/过期材料不启动替任。有效确认重查 term、候选资格、授权、预算和检查点后仅激活指定 term。展示真实已知/估算/未知资源影响，不复制供应商私有 session；等待中独立已批任务继续，需新设计的任务等待。
- **Blocked by：**M3-01、M3-02；沿用 M1-02 已通过的交接语义，不能另建第二套授权路径。
- **关联：**FR03、FR08、FR09、FR12、FR17；PRD-AC04；A02 的上下文交接关联、A11、A20；D02、D07。

## 7. M4：真实恢复、维护和最终 gate

### M4-01｜实际终止、取消竞态与正常恢复

- **目标与 scope：**在完整平台和选定实际 RunnerHost/订阅/API 环境中终止协调器、RunnerHost、工具进程或连接，核对业务/物理/消费三个状态，再恢复有效授权内工作。复测原生权限与 SSE。
- **关键 AC：**覆盖预留提交、accepted、spawn 后 ACK 前、结果落盘、业务成功但子进程存活、send_pending/unknown 各窗口；恢复枚举全部未核对对象，未知不重派。取消失败/失联不释放 writer 或假称服务端停止；迟到结果无交付权但迟到消费入账。第二协调器拒绝接管；未核对前不新派发。以真实进程树和持久/远端记录佐证，不能只 mock inspect 返回值。
- **Blocked by：**M1-06、M3-04、M3-05。按每种已启用 adapter/OS 路径登记覆盖；最终仍缺来源变体的部分交由 M4-03 阻止 v1 放行。
- **关联：**FR10–FR12、FR15–FR18；A09、A10、A18–A20、A23–A26 的完整业务故障组合；PRD-AC04、PRD-AC05。

### M4-02｜备份恢复、升级与保留

- **目标与 scope：**一致数据库/产物/操作记录备份，正常安装升级与资格失效，历史恢复的 epoch/冻结/核对/用户继续决定，磁盘不足/缺产物和保留清理。提供实际可用的本地维护入口与运行说明。
- **关键 AC：**备份后产生执行/消费/撤销/远端变化，再恢复旧快照：旧 activation/outbox 不执行，缺历史保留 unknown，不恢复已撤销权或把旧余额变新钱。用户针对当前核对结果选择继续。缺证据/磁盘满不交付；删除只限真实解析后的受管路径且无活进程。真实备份恢复、数据库迁移和假秘密导出检查均留证。
- **Blocked by：**M1-06、M3-04、M3-05；与 M4-01 并行，复用其故障输入但不等待其结果才能开发维护行为。
- **关联：**FR15、FR17–FR19；A09、A10、A20、A21；D08、D09。覆盖安装、日志保留、秘密不导出及版本兼容要求。

### M4-03｜真实远端 gate、全量证据与 v1 出口

- **目标与 scope：**在用户指定真实仓库完成 2–3 子任务需求，跨来源协作并取得实际 GitHub PR；故障注入交付网络响应、外部 head/base 和取消，完成全部需求/来源/维护及性能审计。此票是验收和必要缺口修复的有界收尾，不承担未实现的大功能。
- **关键 AC：**真实 GitHub 上验证 push/PR 已成功却应答丢失、重复 revision、外部更新、push 后取消、远端 CI 对当前 commit 的关联；无重复 PR/越权覆盖/自动 merge。默认完成和预设 CI gate 分别通过。保存最终实现 commit、必需 CI checks/conclusion、独立 Review、候选/PR/head 与测试证据的对应关系；旧 commit 的 green 不授权新 head。
- **覆盖出口：**FR01–FR20、PRD-AC01–06、A01–A26、D01–D09 的适用行都有真实或正确层级的运行证据；五来源各自合格范围明确，必需角色/工具能力无缺口。not_run/unsupported/缺账号不能静默计为 v1 完成。模型若失败须正确停止且记录，不伪造成功率；记录真实连续运行、修复/等待/费用/未知比例及本地性能测量。
- **Blocked by：**M2-02、M2-03、M2-04、M2-05、M2-06、M4-01、M4-02；其余候选通过传递依赖纳入。需实际仓库/分支/检查与 GitHub 配置；本地 bare remote 不能替代远端 gate 结论。
- **关联：**全部 FR/AC/A；直接复核 FR02、FR13、FR18–FR20，A01、A02、A12–A17、A20、A21，PRD-AC06 及全部非功能指标。结果回填 [需求覆盖审计](../implementation/requirement-coverage.md)，不以 Issue 关闭数计算完成率。

## 8. 发布与实施交接

发布时每票保留本文件标识，绑定 PRD 父任务、实际 Blocked by 关系和对应 FR/AC/A。首次领取时把该票待冻结接口更新为精确版本/证据引用，将具体输入缺口写成配置项；不改成泛化的“做完平台”。

每票交付至少包括：实现 commit/PR、可运行入口、验收输入与命令、实际输出/副作用证据、失败与剩余能力范围。源码或配置变化影响资格时重跑相关用例。发现真阻塞须指出缺失接口/事实，保留可并行工作；不得靠删除要求或填写虚构账户/预算消除阻塞。

M0 的历史“本次发布不实施”描述是当时授权范围的记录；当前扩展目标以最新用户指令和本文为实施安排依据。它不把尚未发生的真实测试、账户配置或远端结果改写为已完成事实。
