# DG07：完整 v1 出口与交付证据

目标：按 #30/#1 的全部原范围验收完整 v1，修复已实现功能的必要收尾缺陷。输入是所有前阶段的当前候选与原证据；不在此处把原必要来源或维护能力改成可选。

## 逐项出口

- [覆盖审计](../../implementation/requirement-coverage.md) 的 FR01–FR20、PRD-AC01–06、A01–A26、D01–D09、G1–G5、US01–US28 追溯和 NF01–NF05 全部有适用层级的当前证据。逐行保留固定输入、实际结果、失败历史、限制及责任票，不以 PR 数量衡量完成。
- 实际机器、真实已有仓库、2–3 子任务、多来源/不同角色、具体计划批准、冻结组合候选、全部 Checks、独立 Review 和同一 PR；默认完成与预设 CI gate 两种模式均成立，产品不自动 merge。
- 五来源各自至少一个声明角色及启用工具真实合格，#8 一订阅加一 API 出口满足。未知身份、unsupported、未授权现金 S 或缺具体配置的必需路径仍是缺口。
- 正常恢复、历史恢复、取消与远端副作用分别有实际故障证据；认证/隔离/秘密、升级备份/保留覆盖实际启用环境。
- NF04 在固定机器/负载/样本下量测普通本地命令/快照 p95 < 1 秒及正常持久事件 2 秒内到 UI，明确排除项；2 writer 加 Review/规划竞争下仍可操作。NF05 连续真实运行按类别保留成功/失败、修复/等待和已知/未知消费，不挑选成功样本。
- 当前 Karajan 实现的双轴独立审查、必需 CI、最终 dev SHA 与产品 PR 的真实 target/head/Checks 分别读回。合并或来源变更后按影响补验，旧 candidate 的通过不自动传播。

## 交付物与停止语义

交付版本化证据索引、可重现运行/维护入口、最终实现/产品 PR 链接、适用来源与限制，并按 Issue 流程逐票核对后关闭完整满足原范围的父票。

仅当以上和所有原 AC 完整满足才报告“v1 交付完成”、完成 DG07 及原父票。必需项仍阻塞时报告“已完成可执行范围，完整 v1 阻塞”，列出最小具体输入/决定及继续条件。`main` 发布和部署需要其具体授权，不是已满足 dev 开发交付的额外条件；也不能假称已发布或已部署。
