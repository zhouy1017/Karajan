# DG06：正常恢复、历史恢复和维护

目标：完成 #28/#29，两个 worker 可分别拥有正常运行恢复与备份维护模块；共享持久状态/epoch 接口先冻结并指定唯一作者。最终组合消费 #16/#26/#27 的实际行为。

## 验收结果

1. #28 正常恢复：实际终止覆盖预留、accepted、spawn/ACK、发送/记账、输出和交付窗口；重启先查询原身份，无重复 writer/调用/PR。进程树、写权、未知远端和迟到结果分别记录，取消不凭本地进程结束推断远端停止或退款。
2. 暂停、取消、重试、换源和人工交接并发时权限与根链消费仍有效；旧批准/term/fence/turn 不重新激活。订阅/API 的适用真实行为逐来源补证。
3. #29 一致备份包含所需数据库、CAS、配置和证据引用；历史恢复生成新 epoch 并冻结，旧 outbox 不自动重放。先核对备份后发生的消费/撤销/远端写入，再由用户对具体当前恢复方案决定继续。
4. 升级、失败回退、缺产物、磁盘满和保留/清理按原范围实测；活动对象及仍被证据引用的受管产物不误删。只对独立测试副本做破坏性故障，不触碰用户原仓库和真实账户历史。
5. 页面重连、快照/事件一致性、有效动作、历史与当前状态清楚区分，维护输出脱敏且可复核。
