# Commander 会话用量统计与实际路由

修订：2026-09-16 r9。状态：按用户要求新增的目标契约，待实现与验收。对应 FR28/29、UX-AC25–27 与 [ADR 0009](../adr/0009-conversation-usage-accounting.md)。本契约扩展 [调用账本](08-provider-gateway.md)、[原生资源账本](02-routing-and-quota.md) 和 [会话读模型](07-commander-workbench-backend-contract.md)，不建立第二份消费事实源。

## 1. 范围与归属

**开发审核待决项：** 已确认全功能开发、来源独立验收；仍待用户决定“无法取得精确实际 provider/token 的来源，是否可在原资格与有限预算门通过后明确标未知并启用，或精确计量也是启用硬门”。下文规定真实数据与缺口如何展示，不构成对任一启用策略的授权。受影响任务使用 `spec:pending-decision`，原能力、严格绑定和预算硬门继续有效。

用户在一个项目的同一 CommanderConversation 中，查看该会话从创建至今的 token 消耗，并按角色、Agent 实例、任务、模型及实际底层路由 provider 分组或交叉筛选。默认覆盖该会话全部 Run，而非仅当前选中 Run；同时包含尚未创建 Run 的 Commander 对话、规划、Designer 创作及顾问调用。确定性步骤本身不消耗模型 token；其触发的模型调用按实际执行身份记账。

| 维度 | 身份与聚合约束 |
|---|---|
| 项目 / 会话 | 使用可信 `project_id/conversation_id`；调用发起时固定归属，切换页面或重命名不迁移消费 |
| Run / 任务 | 保存 `run_id/task_id`、任务 revision 及父任务关系；pre-Run 或 Run 内无具体任务的调用显示明确“无任务”分组，不伪造 Task |
| 角色 | 按稳定角色 ID 汇总，保留调用时的定义 revision 和显示名快照；同名不同角色不合并，改名不重写历史 |
| Agent 实例 | 使用可信角色执行实例身份（ExecutionRef），可展开到 Attempt 或创作执行；同角色多实例分别可查，重试/改派的新 Attempt 保留旧消费 |
| 模型 | 分开记录请求的 alias/ModelBinding revision 和已观测的实际模型 ID；默认模型统计采用实际模型，未知单列，可切换请求模型视角 |
| 实际 provider / 路由 | 保存网关连接/版本、实际 provider、实际模型、脱敏账户引用或已验证池、计费通道及资源池引用；provider 不以模型家族、网关名称或 base URL 推断 |

父任务的“自身消费”和“含子任务消费”分别标注；后者是派生小计，不与子任务再次相加。复用产物、替代任务、扩图或回滚不复制或清零原消费。共享账户的外部消费属于额度观察，不能分摊进当前会话；缺乏可信会话归属的历史记录保留未归属状态并说明历史覆盖缺口，不猜测迁移。

## 2. 最小计量事实与可信路由

在发送前登记 ModelCall 身份及归属，在执行后持久化可关联的回执和用量观察。以下是目标语义，具体存储 schema 由实现切片确定：

| 记录 | 必须保留的内容 |
|---|---|
| 调用归属 | `call_id`、project/conversation、可空 Run/Task、角色版本、ExecutionRef、Attempt 或创作执行身份、授权与请求绑定摘要、发送时间和执行结果 |
| 上游发送与路由观察 | `upstream_attempt_id` 或等效可信发送身份、父 call、可用的上游 request ID、网关/来源证据引用、实际 route 字段及各字段的 known/unknown 状态 |
| 用量观察 | 来源事件身份、覆盖的调用/上游发送/Attempt 集合或游标、原始 usage 与单位、归一化字段、计量映射 revision、服务时间/接收时间、reported/estimated/unknown 状态 |
| 核对记录 | 重复事件判定、观察替代/更正关系、冲突原因、账本 revision 与更新时间；保留原始事实，不以更新汇总覆盖证据 |

实际路由须来自受信适配器、网关或上游的可关联观察，并按固定部署验证证据能力；模型文字自报和配置声明只说明意图。允许 provider 已知但实际模型或账户未知，逐字段展示缺口。多级代理能证明哪一跳就展示哪一跳，不能把已知代理冒充不可见的最终 provider。

一个 Karajan ModelCall 可能对应多次上游发送；已观察到的内部重试、失败发送和获准路由切换均须保留各自 provider 与消费。同一模型经两个 provider 调用，在模型视图可合并查看，在 provider 或模型×provider 视图必须分开。不能观察网关内部发送时标明发送/用量覆盖不完整；此视图不会使原严格绑定或重试资格自动通过。

## 3. Token 口径与缺失数据

基本列为输入 token、输出 token、总 token、调用数；支持时补充缓存读取、缓存写入和推理 token。调用数区分 Karajan 调用与已观测上游发送，不能把网关内部重试隐藏为一次实际请求。各字段缺失用空值和原因表示，已证实无消费才显示零。

每种适配器使用版本化计量映射，保留原始字段和包含关系。归一化输入/输出在可证明覆盖完整且互不重叠时相加为总量；缓存读取/写入可能已包含在输入，推理可能已包含在输出，不能再次相加。仅报告 total 时保留该总量，输入/输出未知；语义不明或 total 与分项不符时保留冲突和来源，不能硬凑平。不同模型的 token 总和仅表示报告数量，不代表相同文本量、单价或成本。

已报告用量、本地估算和未知分别显示。汇总返回已知小计、缺失字段/未知记录数、统计覆盖粒度及完整性，存在缺项时标为“已知小计，仍有用量待核对”，不称完整实耗；估算另列且不能叠加在同一覆盖范围的已报告值上。token、金额（按币种）与请求数、额度百分比等原生单位分开，预算预留或 unknown 保守占账不是实际 token 消耗。金额只在有可信账单或明确价格依据时附带来源/估算标识，本需求不要求由订阅额度推算现金成本。

只有 Attempt 总量的兼容执行器可在该粒度展示并注明限制，不伪造逐调用分摊。若无法证明一个总量只对应单一模型/provider，该维度使用未知/混合未分配分组，不能按当前配置平均分配。全未知与已证实零调用的空会话必须呈现不同状态。

## 4. 去重、失败和恢复

账本对同一来源事件及覆盖范围幂等接收；不能仅凭时间或相同 token 数判断重复。流式累计值不能逐帧累加，终态回执不能与同一调用的中途累计值双计；增量事件按唯一身份累计。网关报告、上游回执及 Attempt 汇总覆盖同一消费时，按可证明的覆盖关系取有效值，不重复加总；无法消除重叠时展示待核对，保留已确认不重叠的小计。

调用失败、超时、用户取消、任务替代以及产物未采用都不删除已发生消费。发送后结果未知保留 pending/unknown；迟到回执按原调用身份核对，受控更正可调整小计并留下 revision，不因任务结束、模型改派或进程重启丢账。执行结果、用量完整性、路由可见性分别记录，成功不等于用量齐全，取消也不等于零 token。

账本为可持久恢复的权威来源；会话、角色、任务、模型、provider 的统计均是同一账本 revision 的投影。每条消费在同一分组口径中最多计一次，未知/无任务组也纳入；交叉维度只是重新分组，不能把多个视图的总数相加。分页只限制返回明细，不截断汇总或漏掉后台任务。

## 5. 会话内读模型与刷新

Hub 常驻摘要显示当前会话已报告 token、用量是否完整及最后更新时间；“用量”入口在同一会话展开分组表及调用详情。角色、Agent、任务、模型、provider 支持组合筛选，并可限定 Run 或时间范围；筛选范围始终可见，返回 Hub 保留草稿与选中状态。

目标只读接口为 `GET /v1/conversations/{id}/usage` 与其 `/records` 明细查询。服务端核验认证主体、project/conversation 归属及所有筛选 ID；不接受跨会话对象混入。摘要返回 filters、grouping、有效计量小计、覆盖/缺失/冲突、as_of/ledger_revision 与事件 watermark；同一查询的总计、分组和分页明细绑定同一快照，过期快照要求重取。角色、任务卡片及详情复用该投影，不另建计数器。

时间范围按调用发起时间（Attempt 粒度按该执行开始时间）筛选，单独显示回执接收/更正时间；迟到记录回到原消费范围，不能以接收日期迁入另一会话或重复计量。历史不足时返回覆盖起点与原因。

用量变化由持久账本事件刷新；断线/重启按 [07](07-commander-workbench-backend-contract.md) 先取快照再续事件，旧会话异步结果不能覆盖当前视图。打开、筛选、排序和刷新统计均不调用模型；用户主动要求自然语言分析时，分析调用本身按所属会话正常记账。浏览器只接收脱敏路由、用量及授权可读的证据引用，不接收网关管理密钥或原始凭据。
