# 设计审阅与决定记录

历史审阅日期：2026-09-05、2026-09-09；承接修订：2026-09-14 r8。第 1–6 节记录原审阅范围、确认和当时验证，不能作为修订日的实现/资格状态。当前产品行为以 [活动 PRD](../prd/commander-workbench.md) 及后续承接契约为准；旧 AC 按原范围保留。

r8 的 [11 角色调度](11-role-directed-scheduling.md) / [ADR 0008](../adr/0008-role-directed-scheduling.md) 已撤销下文历史“两 writer”作为产品默认值的效力。获授权 Workflow 角色按实际任务决定拆分和并行规模，Karajan 不设内置 coding Agent 人数上限；运行图可在原授权内修订。有效身份由 Workflow/grant 定义，可明确授予重叠范围并用 CAS 处理冲突；历史“单一主控”保留同一 grant/交接槽位的当前任期及用户选定主 Commander 交接，不成为全 Run 的角色独占。下方旧数值保留为当时决策记录，不再作为当前实现指令。

下方三角色、原生接入和 PR 路径属于历史基线/默认代码模板；r7 新增可配置职责与拓扑、report/patch 目标及对话式配置真实部署。它们不强制所有 Run 调用 Commander 或创建 PR，也不因新设计而自动通过旧来源/交付验收。

## 4. 2026-09-05 已确认工程基线包

以下在 Q9 获用户整体确认，ADR 0002/0003 当时转为 accepted；“设计基线已确定、待 M0 验证”是该轮记录的状态。

- 技术：Python/FastAPI＋React/TypeScript＋SQLite，模块化后端与独立执行/交付进程；不预建分布式基础设施。
- 执行：版本化 Profile 和资源账本、独立副本、冻结候选、独立验证；当时讨论的交付入口为 PR。r7 模型通道外置，并增加通用 Artifact/Workflow 契约。
- 默认代码 PR 模板的完成定义：必需本地 checks 与独立 Review 通过且 PR 确认创建；远端 CI 单列或事先作为额外门，不自动合并。r7 report/patch 按冻结的各自产物验收完成。
- 可调初值：每项目 2 writer、每 Run 2 轮质量修复、每根任务最多 2 次基础设施重试；所有消费和重试仍受总预算/次数/时间上限限制。
- 历史实施顺序：M0 先用假 provider 和一个订阅端＋一个 API 端验收接口，再扩展链路与选定来源；当前工程顺序以业务/治理文档为准，M0–M4 不充当运行时 Workflow。
- 恢复：历史备份不能当正常重启自动继续；核对后由用户针对恢复状态决定继续，正常重启按原有效授权自动恢复。

该轮设计确认未填写真实金额、启用 Profile、运行服务或编写实现。后续用户授权和实现成果分别按各自会话/Issue 证据认定，不以这一历史句子阻止后来已授权的工作。

- [10 对话式配置与部署](10-conversational-workflow-deployment.md) / [ADR 0007](../adr/0007-conversational-workflow-deployment.md)：Designer 在有限独立授权下实际写配置，文件/图/表同源修订；一次精确确认可发布并部署，或另包含具体输入/Plan 的部署并运行。先准备 pending、调度加载/readback，再 CAS active；准备期间旧 active 有效，旧 Run 保留原快照，未知回执先核对不重复运行。

定义登记、部署 ready 与 Run completed 是不同事实。r7 定稿不表示模型生成、网关来源或真实部署已经验收；新增 GW/WF/WD 用例独立承接，原 Issue 按原 AC 与 C/U/P/S/G 证据继续推进。[治理映射](../planning/design-governance-20260909.md) 负责范围索引，[当前业务顺序](../planning/business-first.md) 负责工程队列。
